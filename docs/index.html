Las piezas

Un Worker, dos entradas, un almacén

No hay ningún servidor encendido todo el tiempo. El código vive en un Cloudflare Worker que solo se ejecuta cuando algo lo despierta: Telegram, cuando pasa algo en el grupo, o el reloj de Cloudflare, cada 5 minutos.

Flujo 1

La bienvenida, en un segundo

Telegram le avisa al bot en cuanto alguien entra. El bot no tiene que preguntar nada: la respuesta sale casi al instante.

  1. 0 s

    Alguien entra al grupo con un enlace de invitación o porque un admin lo agrega.

  2. ~0,2 s

    Telegram llama al Worker en /telegram con el aviso de miembro nuevo y el secreto del webhook.

  3. ~0,3 s

    El Worker comprueba el secreto. Si no coincide, responde 403 y no hace nada. Si entró un bot, lo ignora.

  4. ~1 s

    El bot publica la bienvenida con el nombre de la persona y los tres enlaces.

Si entran varias personas a la vez, el bot las saluda juntas en un solo mensaje.

Comandos

Lo que se le puede pedir

Cualquiera en el grupo puede escribir estos comandos. El bot responde al mensaje con datos consultados a GitHub en ese momento. Telegram los sugiere al escribir /.

ComandoQué responde
/ayudaLos tres enlaces de la bienvenida y la lista de comandos
/prsLos PRs abiertos con la etiqueta l10n-es, los 8 más recientes, con un enlace para ver todos
/issuesLos issues abiertos con la etiqueta l10n-es, para encontrar por dónde empezar
/chatidEl ID del chat. Solo sirve para configurar el bot, por eso no aparece en el menú

En un grupo con varios bots, se escriben con el nombre: /prs@MDNes_bot. Un comando dirigido a otro bot se ignora. Si GitHub no responde, el bot avisa que lo intentes de nuevo en un minuto.

Flujo 2

Los avisos de PRs, cada 5 minutos

No somos administradores de mdn/translated-content, así que GitHub no nos puede avisar directamente. El bot le pregunta cada 5 minutos: “¿cuáles son los 30 PRs más recientes con la etiqueta l10n-es?”.

Cómo sabe qué es nuevo

En cada revisión, el bot compara lo que devuelve GitHub con la lista de PRs que ya avisó, guardada en Workers KV. Avisa solo de los que faltan y los agrega a la lista. Así, cada PR se anuncia una sola vez.

Se publica en el grupo y se agrega a la lista. En la próxima revisión ya no se repite.

#38870 es un número de ejemplo.

La primera vez que se ejecutó, el bot guardó los 30 PRs que ya existían sin avisar de ninguno, para no llenar el grupo de mensajes viejos. Compara por número de PR y no por fecha, así que un PR al que le ponen la etiqueta tarde también se avisa.

Seguridad

Qué es público y qué no

El repositorio es público y no contiene nada que permita usar el bot. Los dos valores sensibles viven solo en Cloudflare.

Dato¿En el repo?Dónde viveQué permite
Token del botNoSecreto en CloudflareEscribir como el bot. Es lo único que hay que proteger de verdad.
Secreto del webhookNoSecreto en CloudflareQue el Worker acepte una petición como si viniera de Telegram
ID del almacén KVSíwrangler.tomlNada sin acceso a la cuenta de Cloudflare
ID del grupoSíwrangler.tomlNada sin el token del bot

Cada petición de Telegram trae la cabecera X-Telegram-Bot-Api-Secret-Token. Si falta, no coincide o el secreto no está configurado, el Worker responde 403 y no hace nada.

Problemas comunes

Alguien entró y el bot no lo saludó

En supergrupos, Telegram a veces no avisa de los miembros nuevos a un bot que no es administrador. Haz a @MDNes_bot administrador; puede quedarse sin ningún permiso.

Se abrió un PR en español y no llegó el aviso

Espera unos 5 minutos después de que el PR tenga la etiqueta l10n-es. Si el PR no tiene la etiqueta, el bot no lo ve. Puedes revisar los registros en vivo con npx wrangler tail.

El bot no responde a /chatid

Comprueba que el bot sea miembro del grupo y escribe el comando con su nombre: /chatid@MDNes_bot.

Quiero cambiar la frecuencia de revisión

Edita crons en wrangler.toml. Por ejemplo, */15 * * * * revisa cada 15 minutos.

Hay que cambiar el token del bot

Genera uno nuevo con @BotFather, guárdalo con npx wrangler secret put TELEGRAM_BOT_TOKEN desde una terminal normal y vuelve a registrar el webhook con npm run set-webhook.
